# ASD-STE100 writing rules

Shared rule set for every human-readable text that wise writes or helps
write: PR descriptions, PR and review comments, commit bodies, tickets,
chat messages, docs, and reports. The rules come from ASD-STE100
Simplified Technical English and are condensed for software work.

`wise-human-writing` decides the structure, the altitude, and the markup
of a message. This file decides how each sentence is written. Apply both.

## Scope

- Apply these rules to prose that a person reads.
- Do not change code, commands, file paths, identifiers, version numbers,
  URLs, or quoted error text. Keep them verbatim.
- Do not change text that the user wrote and asked you to keep.

## Words

1. Use one term for one thing. Do not change the term in the same text.
   If you write "the worker", do not later write "the job runner".
2. Use the simplest common word that has the correct meaning. Write
   "use", not "utilize". Write "start", not "initiate".
3. Give each word only one meaning in the text. Do not use "run" for a
   process and also for a test result.
4. Use verbs for actions. Write "The hook validates the payload", not
   "The hook performs validation of the payload".
5. Use only these verb tenses: simple present, simple past, simple
   future, and the imperative.
6. Do not use the "-ing" form of a verb as a noun or a modifier.
   Write "when you open the PR", not "when opening the PR".
7. Keep the articles "the", "a", and "an". Do not drop them to shorten
   a sentence.
8. Do not stack more than three nouns in one noun phrase. Write "the
   timeout of the retry queue", not "the retry queue worker timeout
   value".
9. Define an abbreviation at its first use, unless it is a standard
   term such as API, CI, or PR.

## Sentences

1. Write a maximum of 20 words in an instruction sentence.
2. Write a maximum of 25 words in a descriptive sentence.
3. Write only one instruction in a sentence.
4. Start an instruction with a verb in the imperative. Write "Run the
   tests", not "The tests should be run".
5. Use the active voice. Write "The CI rejects the build", not "The
   build is rejected".
6. Use a pronoun only when its referent is clear and close.
7. Put a condition before the instruction that it controls. Write "If
   the check fails, revert the change".
8. Do not use semicolons to join two sentences. Write two sentences.

## Paragraphs and procedures

1. Write one topic in a paragraph.
2. Write a maximum of six sentences in a paragraph.
3. Use a numbered list for steps that occur in a sequence.
4. Use a bulleted list for items that have no sequence.
5. Put a warning or a caution before the step that it applies to.
   State the risk and the action to prevent it.

## Check before you post

1. Count the words in each long sentence. Split a sentence that is
   too long.
2. Find each passive verb. Change it to the active voice when you know
   the agent.
3. Find each "-ing" word. Change it to a simple tense or a noun.
4. Find each term for the same thing. Use only one of them.
5. Make sure that each fact, number, and failure from the source is
   still in the text.
